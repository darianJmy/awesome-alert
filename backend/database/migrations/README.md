# 数据库初始化与迁移

应用正常启动只连接并校验数据库版本，不再执行 `AutoMigrate`、历史数据修复或 `seed`。

## 全新数据库

准备一个空的 MySQL 数据库并配置 `DB_DSN`，只执行一次：

```bash
cd backend
go run ./cmd/dbinit
```

该命令会创建全部表、初始菜单、权限、管理员账号，并写入 `schema_migrations`。数据库不是空库时命令会拒绝执行，避免覆盖已有数据。

发布前如需生成一个可供首次部署直接导入的 SQL，请对一个空的临时数据库执行：

```bash
cd backend
go run ./cmd/dbinit --sql-output ../deploy/aiops-init.sql
```

输出文件包含完整表结构、初始菜单、权限和管理员数据。为防止误覆盖，目标 SQL 文件已存在时命令会拒绝写入。该临时数据库只用于构建初始化 SQL，不要指向生产数据库。

默认管理员账号为 `admin / admin123`，首次登录后应立即修改密码。

## 已有数据库升级到版本化迁移

确认已有数据库已经由当前代码成功启动过后，只登记一次基线版本：

```bash
cd backend
go run ./cmd/dbinit --baseline
```

也可以人工执行 `V2026090101__baseline_existing_database.sql`。基线操作只创建版本表并写入版本号，不修改菜单或业务数据。

## 后续版本

每次数据库变更新增一个不可修改的 `V<时间版本>__<说明>.sql` 文件。部署时按版本号顺序执行尚未记录的 SQL，并在同一发布步骤向 `schema_migrations` 写入对应版本。已发布的迁移文件禁止改写。

生产环境只在首次部署时导入生成的初始化 SQL，之后只执行新增的版本化迁移。

## 拨测规则组（2026090701）

已有数据库执行 `V2026090701__inspection_rule_groups.sql`，然后启动新版后端。迁移创建独立拨测规则组和任务所属组字段，现有任务归入 ID 为 1 的默认规则组；任务 ID、配置和历史记录保留。该迁移支持重复执行。

全新数据库的 `dbinit` 会创建相同结构及默认规则组，无需额外执行迁移。默认组不能删除；其他组需先移出或删除组内任务后才能删除，数据库外键同时防止产生孤立任务。

拨测 YAML 配置新增可选 `group_id`，旧配置默认归入默认组。在规则组内导入时，导入目标为当前组，重名匹配仅在组内进行；组内导出仅包含该组任务。
