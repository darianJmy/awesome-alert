# 工作流 DAG 编排与执行

## 产品边界

工作流定位为脚本自动化编排器。新建流程只提供执行脚本、条件判断和结束三类节点；开始节点直接承载手动、定时任务或故障中心传入的流程输入。HTTP 请求、等待、通知、拨测任务以及旧流程输入/输出节点仅为历史流程保留执行兼容，不再允许新增。

## 决策

工作流使用显式有向无环图（DAG），不再根据节点数组顺序推断连线。每个节点保存画布坐标、是否由开始节点触发，以及普通出口或 IF 的 TRUE/FALSE 出口。

## 执行语义

- 开始节点可以连接多个根节点，根节点并发启动。
- 普通节点可以连接多个后继节点，后继分支并发启动。
- 节点只负责执行并产出结构化结果；无论结果成功或失败，显式图都会沿连线继续传播。
- IF 节点从 `steps.<key>.status` 或 `steps.<key>.output` 读取上游结果并选择分支，执行节点不感知后续节点类型。
- IF 只激活 TRUE/FALSE 中的一条边，另一条边标记为未激活。
- 汇合节点等待所有上游边得到“激活”或“未激活”结论；至少一条边激活时执行，否则跳过并向下传播未激活状态。
- 一个节点在一次工作流执行中最多运行一次。
- 没有后续连线的叶子节点可以自然结束流程。结束节点是可选的显式结果声明：一旦流程使用结束节点，每条分支都必须闭合到结束节点；结束节点可声明流程最终为成功或失败，并使用模板返回最终输出。
- 存在结束节点时，中间脚本失败不会直接决定整个流程状态；流程可以通过 IF 进入恢复分支，最终状态由实际执行的结束节点决定。
- 保存时拒绝自连接、循环、失效连线和无法从开始节点到达的节点。

## 兼容性

旧的顺序工作流在读取时迁移为 `graph_version: 2`：第一个节点连接开始节点，普通节点顺序连接，旧 IF 的 `skip_next` 转换为对应目标。未重新保存的旧流程仍遵循原有 `on_failure` 停止/继续策略；保存为显式图后移除该字段。旧的“结束”分支会在编辑器中显示为未连接，用户需要补充实际连线后才能保存。

已有 HTTP、等待、通知、拨测任务、流程输入和流程输出节点继续按原语义加载与执行。编辑器只展示当前历史节点自身的类型，不提供切换或新增其他历史节点的入口。

## 常驻进程

并行调度不等于进程托管。脚本若一直不退出，工作流会持续等待并最终受节点超时限制。需要长期运行的服务应由 systemd、容器编排等进程管理器托管；工作流脚本负责启动或变更服务后返回，再由并行分支执行请求或检查。
