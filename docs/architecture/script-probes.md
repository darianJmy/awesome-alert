# 脚本拨测

周期性健康检查统一进入「拨测中心 → 拨测任务」。新建或编辑任务时选择「脚本 · 脚本运行」，选择脚本库中的 Shell/Python 脚本、执行节点、周期及故障中心。在任务新建或编辑页点击「测试拨测」即可试运行，试运行不会保存拨测记录或触发通知。

## 执行与结果

- 每次执行读取脚本库最新内容；脚本不存在、已停用或配置无效时，拨测失败。
- 支持服务端、SSH、Agent 节点；多节点各自记录结果、维护失败/恢复计数和告警。
- 退出码 `0` 表示成功；非零退出码、执行异常和超时表示失败。标准输出和标准错误合并展示在结果中。
- 超时可设为 100–300000ms，页面默认 30000ms。节点需要 Bash、GNU `timeout`；Python 脚本需要 Python 3。Git 来源脚本沿用脚本库的仓库执行方式。
- 最近拨测记录展示退出码、输出和错误信息，输出最多保留 64KiB，并标记截断；成功率和耗时趋势复用现有拨测统计。
- 调度最低周期为 10 秒；最多同时调度 8 个任务，每个任务最多并行 8 个节点。同一任务已有执行未结束时不重复启动，长脚本不阻塞告警调度。
- 被拨测任务引用的脚本不能直接删除，需先修改或删除引用任务。脚本停用后，引用它的拨测任务会按失败处理。

配置仍存储于拨测任务的 `config`，不新增任务表。例如：

```json
{
  "script_id": 12,
  "timeout_ms": 30000,
  "execution_nodes": [{ "node_type": "direct", "node_id": 0 }],
  "alert_detail": "核心进程健康检查失败"
}
```

现有 YAML 导入/导出支持相同配置；导入时脚本 ID 必须指向当前平台的有效脚本。

## 独立定时任务下线

旧的定时任务页面、API、Cron 调度和新增权限入口已移除。旧菜单在服务端菜单返回时过滤，旧页面地址跳转到拨测任务。脚本库、工作流和自动化处置继续保留。

旧定时任务及执行记录保留在数据库中，不删除、不继续执行。服务启动时终止仍活跃的旧定时任务告警，历史告警和通知记录仍可查询。旧 Cron 表达式、工作流定时任务不自动转换为固定周期脚本拨测；需要继续的健康检查，应按新配置创建脚本拨测任务。

## 开发验证

执行 `go test ./...` 验证后端；前端使用 Vite 开发模式，无需生成 `web/dist`。新增测试覆盖 Shell/Python 真实执行、退出码、超时、输出截断、脚本引用保护、配置 CRUD/导入、告警触发与恢复、调度与旧接口下线。

独立的即时拨测页面与菜单已移除，旧地址跳转到新建拨测任务。任务编辑页继续使用 `/api/instant-probe` 测试接口，无需先保存任务。
